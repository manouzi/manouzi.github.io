Qui utilise cette table ?Who uses this table?

Avant de supprimer une table, on regarde qui la lit. Le lignage répond en partie : sur le projet, il voit les modèles et les tests, et rate trois lecteurs sur trois.Before deleting a table, you check who reads it. Lineage answers in part: on the project, it sees models and tests, and misses three readers out of three.

Une table qui semble inutile coûte du stockage, du temps de calcul et de l’attention. La supprimer est tentant ; la question qui précède est toujours la même : qui la lit ? Le lignage, ce graphe que dbt tient entre les tables, en donne une réponse, mais seulement pour ce qu’il connaît.A table that looks useless costs storage, compute time and attention. Deleting it is tempting; the question that comes first is always the same: who reads it? Lineage, the graph dbt keeps between tables, gives an answer, but only for what it knows.

Sur le projet, la table stg_fabrication prépare les ordres de fabrication. Dans le graphe de dbt, qui compte 27 modèles, elle n’a aucun modèle en aval : seulement 4 tests, et aucune exposition déclarée. À le lire, la supprimer ne casserait rien.On the project, the table stg_fabrication prepares work orders. In the dbt graph, which has 27 models, it has no downstream model: only 4 tests, and no declared exposure. Reading the graph, deleting it would break nothing.

Une recherche dans le code du projet trouve pourtant 3 traitements qui la lisent directement : les comptes de la page du projet, la démonstration sur le taux de livraison, la démonstration sur le rebut. Aucun ne passe par dbt, et le graphe ne les connaît pas. Supprimer la table les casserait tous, à leur prochaine exécution.Yet a search in the project’s code finds 3 processes that read it directly: the counts on the project page, the delivery rate demonstration, the scrap demonstration. None goes through dbt, and the graph does not know them. Deleting the table would break all of them on their next run.

Le lignage ne voit que ce qui lui est déclaré. Les extractions écrites à côté, les rapports d’un outil branché sur la base, les requêtes d’un analyste ou un fichier tableur relié à la table restent hors du graphe. dbt permet de déclarer ces usages comme des expositions, avec leur type et leur propriétaire ; le projet ne l’a pas encore fait pour ces trois lecteurs.Lineage only sees what it is told about. Extracts written on the side, reports from a tool plugged into the database, an analyst’s queries or a spreadsheet linked to the table stay outside the graph. dbt lets you declare these uses as exposures, with their type and owner; the project has not yet done so for these three readers.

Avant de supprimer, il faut donc croiser trois sources : le graphe, une recherche dans le code, et le journal des requêtes de la base quand il existe. Ce qui reste inconnu après ces trois sources justifie une étape de plus : retirer d’abord l’accès à la table, attendre, et ne supprimer qu’ensuite.Before deleting, you therefore need to cross three sources: the graph, a search in the code, and the database’s query log when there is one. Whatever stays unknown after those three sources justifies one more step: first remove access to the table, wait, and only then delete it.
