Le pipeline est vert, les chiffres sont fauxThe pipeline is green, the numbers are wrong

Un lot livré deux fois ne fait échouer aucune tâche : la nuit est verte et les ventes doublent. Ce qu'un contrôle de doublons voit, et ce qu'il coûte, mesuré sur le projet.A batch delivered twice makes no task fail: the night is green and sales double. What a duplicate check sees, and what it costs, measured on the project.

Une chaîne de nuit peut finir entièrement verte et livrer des chiffres faux. Le cas le plus simple : la source dépose deux fois le même lot. La tâche de chargement lit le fichier, écrit les lignes et réussit. Toutes les tâches en aval réussissent aussi, puisqu'elles reçoivent des données valides, seulement en double.A nightly pipeline can finish entirely green and deliver wrong numbers. The simplest case: the source drops the same batch twice. The load task reads the file, writes the rows and succeeds. Every downstream task succeeds as well, since it receives valid data, only duplicated.

Sur le projet, la table brute des ventes Internet compte 60 398 lignes. Livrée deux fois, elle passe à 120 796, la table des ventes passe de 121 253 à 181 651 lignes, et le chiffre d'affaires Internet du jeu d'exemple, 29 358 677 $, apparaît doublé dans le rapport du matin. Aucun statut ne le signale : chaque tâche a fait ce qu'on lui demandait.On the project, the raw Internet sales table has 60,398 rows. Delivered twice, it becomes 120,796, the sales table goes from 121,253 to 181,651 rows, and the sample data's Internet revenue, $29,358,677, shows up doubled in the morning report. No status flags it: every task did what it was asked to do.

Ce qui le voit est un contrôle sur les données, posé sur la table qui reçoit le lot. Dans la chaîne Dagster du projet, il s'appelle pas_de_lot_en_double : il compte les lignes qui partagent la même clé (SalesOrderNumber, SalesOrderLineNumber) et échoue s'il en trouve une seule. C'est l'un des 51 contrôles de chaque nuit.What catches it is a check on the data, attached to the table that receives the batch. In the project's Dagster pipeline it is called pas_de_lot_en_double: it counts rows sharing the same key (SalesOrderNumber, SalesOrderLineNumber) and fails if it finds a single one. It is one of the 51 checks run every night.

Un statut dit si une tâche a tourné, pas si son résultat est plausible. Un contrôle de volume le complète : comparer les lignes écrites cette nuit à celles de la veille, et alerter au-delà d'un écart fixé d'avance. Dans le projet, l'agent d'astreinte lit justement ces volumes, 60 398 lignes la veille et 120 796 cette nuit, avant de proposer une action.A status says whether a task ran, not whether its result is plausible. A volume check complements it: compare the rows written tonight with those of the previous night, and alert beyond a threshold set in advance. In the project, the on-call agent reads exactly these volumes, 60,398 rows the night before and 120,796 tonight, before proposing an action.

Ce contrôle coûte une requête de regroupement sur la table. Mesuré sur le poste du projet, il prend 2,3 millisecondes pour 60 398 lignes, médiane de 7 mesures. À cette échelle, le coût est négligeable ; sur une table de plusieurs milliards de lignes, on le restreint au lot du jour plutôt qu'à toute la table.This check costs one grouping query on the table. Measured on the project's machine, it takes 2.3 milliseconds for 60,398 rows, median of 7 measurements. At this scale the cost is negligible; on a table of several billion rows, it is restricted to the day's batch rather than the whole table.

Le plus coûteux est ailleurs : décider de ce que fait l'échec. Un contrôle qui avertit sans bloquer laisse partir le rapport ; un contrôle qui bloque retarde tout le monde pour un faux positif. Dans le projet, l'échec bloque l'actualisation du rapport, et l'astreinte rejoue la date pour remplacer le lot au lieu de l'ajouter une troisième fois.The real cost lies elsewhere: deciding what the failure does. A check that warns without blocking lets the report go out; a check that blocks delays everyone for a false positive. In the project, the failure blocks the report refresh, and the on-call engineer replays the date to replace the batch instead of appending it a third time.
