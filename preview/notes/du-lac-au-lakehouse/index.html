Du lac au lakehouseFrom lake to lakehouse

Stockage en lakehouse : journal de transactions, versions et couchesLakehouse storage: transaction log, versions and layers

Le lac de données promettait de tout garder pour presque rien. Le lakehouse garde les fichiers et ajoute ce qui manquait : un journal qui dit quels fichiers forment la table à chaque instant. De là viennent les écritures sûres, le retour en arrière et la lecture par plusieurs moteurs.The data lake promised to keep everything for next to nothing. The lakehouse keeps the files and adds what was missing: a log that says which files make up the table at any moment. Safe writes, going back in time and reading by several engines all follow from it.

Quatre mille fichiersFour thousand files

Dans beaucoup d'entreprises, le lac de données (data lake) est parti d'une bonne idée : tout garder, en fichiers, pour presque rien. Quelques années plus tard, le dossier des ventes contient quatre mille fichiers : des exports CSV, des Parquet rangés par date, les doublons d'un lot relancé, un fichier à moitié écrit pendant une coupure. Personne ne sait dire lesquels forment la table des ventes d'aujourd'hui.In many companies the data lake started from a good idea: keep everything, as files, for next to nothing. A few years later the sales folder holds four thousand files: CSV exports, Parquet files sorted by date, duplicates from a rerun batch, a file half written during an outage. Nobody can say which of them make up today's sales table.

Une table, c'est des fichiers et un journalA table is files plus a log

Le lakehouse garde les fichiers et leur ajoute ce qui manquait : un journal des transactions (transaction log). Dans le format Delta, c'est un dossier _delta_log qui reçoit un fichier JSON par version. Chaque entrée dit quels fichiers de données entrent dans la table et lesquels en sortent. La table, à une version donnée, est la liste des fichiers ajoutés et pas encore retirés.The lakehouse keeps the files and adds what was missing: a transaction log. In the Delta format it is a _delta_log folder that receives one JSON file per version. Each entry says which data files join the table and which leave it. The table, at a given version, is the list of files added and not yet removed.

Chaque opération de la figure 1 a réellement été jouée avec la bibliothèque deltalake sur les commandes de l'entreprise, et les noms de fichiers affichés sont ceux qu'elle a écrits. On ne modifie jamais un fichier. Corriger une commande réécrit le fichier qui la contient ; effacer un client aussi. L'ancien fichier reste sur le disque, mais le journal le sort de la table. C'est ce qui rend l'écriture sûre : tant que la nouvelle entrée du journal n'existe pas, un lecteur voit la version précédente en entier, jamais un état à moitié fait.Every operation in figure 1 was run with the deltalake library on the orders of the sample data, and the file names shown are the ones it wrote. A file is never modified. Correcting an order rewrites the file that holds it; deleting a customer does too. The old file stays on disk, but the log takes it out of the table. That is what makes writes safe: until the new log entry exists, a reader sees the whole previous version, never a half-finished state.

Remonter le tempsGoing back in time

Puisque les anciens fichiers restent, chaque version reste lisible : on peut remonter le temps (time travel). La figure 2 reprend la relance fautive de la note « Orchestrer » : à la version 7, le lot du 14 novembre entre une seconde fois, et la journée passe de 54 233 $ à 108 467 $. Restaurer la version 6 (restore) n'efface rien : la bibliothèque écrit une version 8 dont l'entrée du journal retire le fichier fautif. Le total redevient juste, et l'erreur reste visible dans l'historique.Since old files stay, every version stays readable: you can go back in time (time travel). Figure 2 replays the faulty rerun from the note "Orchestrating": at version 7 the batch for 14 November goes in a second time, and the day jumps from $54,233 to $108,467. Restoring version 6 deletes nothing: the library writes a version 8 whose log entry removes the faulty file. The total is right again, and the mistake stays visible in the history. Le revers : les fichiers sortis de la table occupent toujours de la place, et chaque petit chargement ajoute un petit fichier. On regroupe donc régulièrement (compaction) : à la version 9, la bibliothèque a fusionné 5 fichiers actifs en un seul. Le dossier contient alors 9 fichiers de données, dont un seul compte. Une commande de nettoyage (vacuum) supprime ensuite ceux qu'aucune version conservée n'utilise plus.The downside: files taken out of the table still take up space, and every small load adds a small file. So you compact regularly: at version 9 the library merged 5 active files into one. The folder then holds 9 data files, of which only one counts. A cleanup command (vacuum) then deletes those that no retained version uses any more.

Bronze, argent, orBronze, silver, gold

Le journal rend la table fiable ; il ne dit rien de la qualité de ce qu'elle contient. On range donc les données en trois couches, que Databricks décrit sous le nom d'architecture en médaillon (medallion), de la couche bronze, la plus brute, à la couche or, prête à l'emploi, en passant par l'argent. La figure 3 suit une vraie ligne de commande, la première de la commande SO70752 du 14 novembre.The log makes the table reliable; it says nothing about the quality of what is in it. So data is kept in three layers, which Databricks describes as a medallion architecture, from the bronze layer, the rawest, to the gold layer, ready for use, by way of silver. Figure 3 follows a real order line, the first line of order SO70752 on 14 November.

En bronze, la ligne est gardée telle que reçue : du texte coupé par des barres verticales, avec la date écrite en toutes lettres comme dans la source, en 2013, avant le décalage de douze ans appliqué partout dans ce carnet. Le lot du 14 étant entré deux fois, elle y figure deux fois : 1 086 lignes en tout. En argent, chaque champ a son type et les doublons sont retirés : 911 lignes. En or, les lignes sont rassemblées par jour dans le magasin des ventes : 5 lignes, prêtes pour un rapport. Chaque couche fait une promesse à la suivante, et cette promesse s'écrit et se teste.In bronze the line is kept exactly as received: text split by vertical bars, with the date spelled out as in the source, in 2013, before the twelve-year shift applied throughout this notebook. Since the batch for the 14th went in twice, the line is there twice: 1,086 lines in all. In silver every field has its type and duplicates are removed: 911 lines. In gold the lines are grouped by day in the sales mart: 5 lines, ready for a report. Each layer makes a promise to the next, and that promise is written down and tested.

Un stockage, plusieurs moteursOne storage, several engines

Les fichiers de données d'une table Delta sont du Parquet, un format ouvert, et le journal est du JSON. Tout moteur qui connaît le format lit donc la même table, sans copie ni export. Pour cette note, la table a été écrite par la bibliothèque deltalake en Python, puis relue par DuckDB : 369 commandes et 292 631 $ des deux côtés. Dans Fabric, le principe s'applique à l'échelle d'une entreprise : les traitements Spark, le moteur SQL et Power BI travaillent sur les mêmes tables Delta de OneLake.The data files of a Delta table are Parquet, an open format, and the log is JSON. Any engine that knows the format therefore reads the same table, with no copy and no export. For this note the table was written by the deltalake library in Python, then read back by DuckDB: 369 orders and $292,631 on both sides. In Fabric the same idea works at company scale: Spark jobs, the SQL engine and Power BI all work on the same Delta tables in OneLake.

Où en est le métierWhere the trade stands

État au 13 novembre 2026. Deux formats de table ouverts occupent ce terrain : Delta Lake, utilisé dans cette note, et Apache Iceberg. Ils se rapprochent. La fonction UniForm de Delta génère des métadonnées Iceberg pour qu'un client Iceberg lise une table Delta. La version 3 de la spécification Iceberg ajoute entre autres des vecteurs de suppression binaires (deletion vectors), le suivi de l'origine des lignes et de nouveaux types ; une version 4 est en préparation. Autour des formats, les catalogues tiennent la liste des tables et des droits : Apache Polaris, par exemple, est un catalogue ouvert pour Iceberg qui implémente son interface REST.As of 13 November 2026. Two open table formats hold this ground: Delta Lake, used in this note, and Apache Iceberg. They are moving closer. Delta's UniForm feature generates Iceberg metadata so that an Iceberg client can read a Delta table. Version 3 of the Iceberg specification adds, among other things, binary deletion vectors, row lineage tracking and new types; a version 4 is under development. Around the formats, catalogs keep the list of tables and permissions: Apache Polaris, for example, is an open catalog for Iceberg that implements its REST interface.

Chez Microsoft, OneLake présente une table Delta aussi en Iceberg, et l'inverse, par une virtualisation des métadonnées ; un raccourci (shortcut) vers une table Iceberg la fait apparaître comme une table Delta (documentation du 30 juillet 2026). Le mode Direct Lake de Power BI charge en mémoire les tables Delta de OneLake : son actualisation ne recopie que les métadonnées (documentation du 2 septembre 2026). DuckDB lit les tables Delta par son extension delta, qui sait aussi en créer et y ajouter des lignes, sans les modifier ni en supprimer. DuckDB a publié en avril 2026 la version 1.0 de DuckLake, un format de lac qui range toutes ses métadonnées dans une base SQL.At Microsoft, OneLake presents a Delta table as Iceberg too, and the other way round, through metadata virtualisation; a shortcut to an Iceberg table makes it appear as a Delta table (documentation of 30 July 2026). Power BI's Direct Lake mode loads Delta tables from OneLake into memory: its refresh copies only metadata (documentation of 2 September 2026). DuckDB reads Delta tables through its delta extension, which can also create them and append rows, without updating or deleting. In April 2026 DuckDB released version 1.0 of DuckLake, a lake format that keeps all its metadata in a SQL database.

Choix techniquesTechnical choices
  • Retenu : la bibliothèque deltalake (delta-rs, écrite en Rust, avec une interface Python) plutôt que Spark : elle s'installe avec le reste du pipeline, sans machine Java, et tourne sur un portable.Chosen: the deltalake library (delta-rs, written in Rust, with a Python interface) rather than Spark: it installs with the rest of the pipeline, needs no Java machine and runs on a laptop.
  • Retenu : DuckDB relit la table par son extension delta ; la construction vérifie que les deux lectures donnent le même nombre de commandes et le même total.Chosen: DuckDB reads the table back through its delta extension; the build checks that both reads give the same number of orders and the same total.
  • Retenu : Delta plutôt qu'Iceberg pour cette note, parce que c'est le format natif de OneLake, celui que rencontre d'abord un lecteur venant de Fabric.Chosen: Delta rather than Iceberg for this note, because it is OneLake's native format, the one a reader coming from Fabric meets first.
  • Retenu : noms de fichiers, versions et entrées du journal exportés tels que la bibliothèque les a écrits (src/data/b2/lakehouse.json).Chosen: file names, versions and log entries exported exactly as the library wrote them (src/data/b2/lakehouse.json).

LimitesLimits

  • La table Delta est écrite sur un disque local, pas sur OneLake ni sur un stockage cloud.The Delta table is written to a local disk, not to OneLake or cloud storage.
  • 5 jours de commandes seulement, pour que chaque fichier du journal reste lisible.Only 5 days of orders, so that each log file stays readable.
